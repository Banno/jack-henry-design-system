# Primitives

Primitives are low-level building blocks for arranging other
components. They carry no visual styling of their own, and that is exactly what
makes them powerful. They give you a consistent, token-aware way to handle
spacing, alignment, and layering, so every screen in your app lines up the same
way with very little code.

## Layout primitives

- **[Row](?path=/docs/primitives-row--docs)**: arranges its children in a
  horizontal row.
- **[Column](?path=/docs/primitives-column--docs)**: arranges its children in a
  vertical column.
- **[Stack](?path=/docs/primitives-stack--docs)**: layers its children on top of
  one another in a shared cell.

`Row` and `Column` expose `gap` and `padding` (mapped to dimension tokens) along
with `align-x`, `align-y`, `wrap`, and `reverse`. `Stack`
exposes `align-x` and `align-y` for positioning its layers.

## Working with slotted items

`Row` and `Column` set the Flexbox properties on the **container**: direction,
gap, wrapping, and alignment. Properties that belong to the **individual items**
are yours to set on the slotted elements themselves. For example, to let one
child grow to fill the remaining space, or to give a single item a different
alignment from its siblings, apply the relevant Flexbox item properties directly:

```css
/* let this child absorb the leftover space in a row */
.flexible { flex: 1; }

/* override alignment for just one item */
.pinned { align-self: start; }
```

The same applies to `order`, `flex-grow`, `flex-shrink`, and `flex-basis`. The
primitive arranges the container, and you fine-tune individual items as needed.

## Composition

The real payoff comes from combining them. A `Row` can hold `Column`s, a `Column`
can hold `Row`s, and a `Stack` is itself a valid flex child, so they nest freely
to build toolbars, cards, form rows, and more. See
**[Layout Composition](?path=/docs/primitives-layout-composition--docs)** for
real-world patterns.
