# Glossary

Use the following terminology over other conventions unless otherwise noted.

- **Alias (token):** a contextualized type of design token that references another (typically global) token. The same as a semantic design token.
- **Author:** a designer or engineer that consumes the design system in order to build products/applications.
- **Component:** a reusable block of code, tokens, and/or other components composed to serve a specific function. Not to be confused with a pattern.
- **Component library:** a collection of browseable components accompanied by implementation reference and other relevant technical documentation.
- **Composite (token):** a design token whose value is made up of multiple, named child values.
- **Design kit:** a comprehensive visual representation of components, styles, and assets, structured so designers can create, edit, or expand on existing components without building them from scratch, and consistently and rapidly create and iterate interface mockups.
- **Design system:** a complete and organized set of guidelines, components, and other relevant resources necessary to help users consistently and efficiently create cohesive digital products.
- **Design token:** a way of expressing design decisions in a platform-agnostic way so they can be shared across different disciplines, tools, and technologies, helping establish a common vocabulary across organizations.
- **Engagement:** the processes that control decision-making, contribution, enhancements, and workflows for the design system. Also often referred to as governance.
- **Global (token):** a highly-abstracted type of design token that represents one of a series of options available for use in building and extending the system. The same as a primitive design token.
- **Grade:** a particular level of value; similar terms may be level or step.
- **Guidelines:** suggestions and best practices for how to best use the various facets of the design system.
- **Library:** a published design file that contains reusable design elements such as variables, styles, icons, and components.
- **Pattern:** a reusable best-practice solution for how a user achieves a goal or solves a design problem. Not to be confused with a component.
- **Style hook:** a component-specific way to represent and customize a design decision. Previously referred to as a component token — use style hook as the official term, though "component token" may be used as needed for clarification.
- **Toolkit:** the collection of resources and technologies necessary to effectively build products that seamlessly integrate with other Jack Henry products.
- **User:** the end user interacting with design system components that have been integrated into the product.
- **Variable:** reusable values that can be applied to design properties and prototyping actions. Figma uses "variable" to represent the concept of design tokens, and the two terms are often used interchangeably — though variables are platform-specific, with opinions and constraints that don't necessarily apply to the tokens they derive from. A token can be represented as either a variable or a style within Figma.
- **Visual language:** a unified and specific set of guidelines that thoughtfully and intelligibly describes how the design system should look and feel.
