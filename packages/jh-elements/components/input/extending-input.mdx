# Extending jh-input

The jh-input component is built for composition using template method overrides.

When extending `jh-input`, you should override targeted sub-rendering methods rather than rewriting the full `render()` block. This preserves critical built-in lifecycle behaviors, including input masking, event dispatching, and accessibility associations.

## Overridable Template Methods

      <td>renderLeftSlot()</td>
      <td>`@slotchange=${this._handleSlotChange}`</td>

    </tr>
    <tr>
      <td>renderRightSlot()</td>
      <td>`@slotchange=${this._handleSlotChange}`</td>
      <td>Renders the right slot. Override this to inject a permanent element in the slot. The handler dynamically toggles slot visibility and sets any slotted `jh-icon` or `jh-button` components to `size="x-small"`.</td>
    </tr>
    <tr>
      <td>renderLabel()</td>
      <td>None</td>
      <td>Displays the text label, required/optional indicators, and the helper text. See [Extension Guardrails](#extension-guardrails) for additional important considerations when overriding this method.</td>
    </tr>
    <tr>
      <td>renderFooter()</td>
      <td>`this.handleMaxlength()`</td>
      <td>Displays the lower layout containing error text and the character counter. It calls the maxlength handler automatically when the character limit is reached. See [Extension Guardrails](#extension-guardrails) for additional important considerations when overriding this method.</td>
    </tr>
  </tbody>
</table>

## Extension Guardrails

If you choose to override `renderLabel()` or `renderFooter()` you must maintain the underlying `id` and `aria-describedby` string contracts. `jh-input` dynamically wires helper text and errors together using `this.uniqueId`. Breaking this structure will break screen reader support.

#### For `renderLabel()` overrides
- Label Association: The native `<label>` element must use `for="jh-input-${this.uniqueId}"`.
- Helper Text ID: The element wrapping your helper text must use `id="jh-input-helper-${this.uniqueId}"`.

#### For `renderFooter()` overrides
- Error Text ID: The element wrapping your error text must use `id="jh-input-error-${this.uniqueId}"`.
- Character Counter Responsibility: Because `renderFooter()` owns the counter feature, omitting it means showCharCount and maxlength visual tracking will be disabled. To retain the counter, you must manually check `this.showCharCount`, construct the string, and explicitly invoke `this._handleMaxlength()` when the character limit is reached.

## Extension Example

The example below creates a subclass that overrides `renderFooter()` to add a warning icon next to the error message. Notice how it explicitly reuses `this.uniqueId` to keep the aria-describedby association. For the purposes of the example, note that the example removes the built-in character counter functionality.

```javascript
import { html } from 'lit';
import { JhInput } from '@jack-henry/jh-elements/components/jh-input/jh-input.js';
import '@jack-henry/jh-icons/icons-wc/icon-triangle-exclamation.js';

export class JhCustomErrorInput extends JhInput {
  renderFooter() {
    let errorText = null;

    // Custom Error UI with Preserved Accessibility Contract
    if (this.invalid && this.errorText) {
      errorText = html`
        <!-- CRITICAL: The id MUST match 'jh-input-error-${this.uniqueId}' -->
        <p id="jh-input-error-${this.uniqueId}" class="error-text custom-alert-style">
          <jh-icon-triangle-exclamation size="x-small"></jh-icon-triangle-exclamation>
          <span>${this.errorText}</span>
        </p>
      `;
    }

    if (errorText) {
      return html`
        <div class="footer-content">
          ${errorText}
        </div>
      `;
    }
    return null;
  }
}
customElements.define('jh-custom-error-input', JhCustomErrorInput);
```
