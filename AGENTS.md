# Working in this repo as an agent

This is the Forge Design System monorepo (pnpm workspaces). It publishes web components, design tokens, and icons under the `@jack-henry/*` scope. The code prefix is `jh-`; the word "Forge" does not appear in package or tag names.

## Sources of truth

Read these before writing any code that uses or changes a component. Do not infer an API from the source when a contract exists.

| What | Where | Nature |
|---|---|---|
| Component API (attributes, properties, slots, events, CSS custom properties, deprecations) | `packages/jh-elements/custom-elements.json` | Generated. Never edit by hand. |
| Component intent (purpose, when to use, when not to, composition, accessibility, style-hook zones) | `packages/jh-elements/components/<name>/<name>.md` | Handwritten. One per component. |
| Design tokens, resolved per theme | `packages/jh-tokens/platforms/json/json-flat/jh-theme-light.json` and `jh-theme-dark.json` | Generated. Every token has `token`, `value` (alias target), `computedValue`, `description`, `deprecated`. |
| Token definitions (source) | `packages/jh-tokens/tokens/{global,alias,light,dark}/*.json` | Handwritten DTCG-style JSON, built with Style Dictionary. |
| Icons | `packages/jh-icons/icons-svg/` (source) and `icons-wc/` (generated `jh-icon-*` elements) | Generated from SVG. |
| Storybook docs | `packages/jh-elements/components/<name>/<name>.mdx` | Human-facing. Not a contract; do not rely on it for API facts. |
| Release rules | `docs/release-guide.md` | |

If `custom-elements.json` and a `<name>.md` disagree, the manifest is right about the API and the MD is right about intent. Flag the mismatch; do not silently pick one.

## Hard rules

1. **Use the hooks, not the values.** Style a component through its `--jh-<component>-*` CSS custom properties (listed under `cssProperties` in the manifest). Never set a token's hex or px value directly, and never override a component's internal selectors.
2. **Semantic tokens over primitives.** When a value is needed, reach for `jh-color-content-*`, `jh-color-container-*`, `jh-color-control-*`, `jh-border-*`, etc. Primitives (`jh-color-gray-950`, `jh-dimension-*`) are for defining semantic tokens, not for consuming in components or apps.
3. **Attributes are kebab-case, properties are camelCase.** The manifest lists both. Boolean attributes are present/absent, never `"true"`/`"false"` — except `accessible-disabled`, which is a string by design.
4. **One component, one folder.** `components/<name>/` holds `<name>.js`, `<name>.d.ts` (generated), `<name>.stories.js`, `<name>.mdx`, and `<name>.md`. Nothing else goes there.
5. **Public API lives in JSDoc.** The manifest is only as good as the JSDoc on the class: `@customElement`, `@slot`, `@fires`, `@cssprop`, and descriptions on every public property. A new attribute, slot, event, or CSS hook without a JSDoc description is incomplete.
6. **Deprecate, don't delete.** Register removals in `packages/jh-elements/scripts/cem-plugins/deprecations.js` so they surface in the manifest before anything is removed. See `docs/release-guide.md` for what counts as breaking.
7. **Do not touch generated files.** `custom-elements.json`, `web-types.json`, `*.d.ts`, `tag-maps`, `jh-tokens/platforms/**`, and `jh-icons/icons-wc/**` are regenerated by the commands below. Edit the source, then regenerate.

## Commands

Run from the repo root.

```sh
pnpm install:all                 # install everything
pnpm define:jh-elements          # regenerate custom-elements.json, web-types.json, .d.ts, tag maps
pnpm analyze:jh-elements         # manifest only
pnpm build:jh-tokens             # rebuild token outputs from tokens/**
pnpm build:jh-icons              # regenerate jh-icon-* web components from SVG
pnpm storybook:jh-elements       # local Storybook on :6006
pnpm generate:jh-elements        # scaffold a new component (hygen)
```

After any change to a component's class or JSDoc, run `pnpm define:jh-elements` and commit the regenerated files with the change.

## Making a change

1. Read `custom-elements.json` for the element and its `<name>.md`.
2. Edit the source (`<name>.js`) and its JSDoc together.
3. Update `<name>.md` if intent, composition, or accessibility rules changed. Do not restate props, types, or defaults there.
4. Regenerate (`pnpm define:jh-elements`) and confirm the diff to `custom-elements.json` is what you intended.
5. Add a changeset: `pnpm changeset` → pick the package and bump level per `docs/release-guide.md` (visual-only changes are `patch`, tagged "visual change" in the summary).
6. Open the PR against `next`. The PR template asks for a DSPD/Jira reference; include it.

## Adding a component

Scaffold with `pnpm generate:jh-elements`, then fill in, in this order: JSDoc on the class, `<name>.md` from the template in `components/_template/component.md`, stories, MDX. A component is not done until the manifest shows its slots, events, and CSS hooks with descriptions and `<name>.md` exists.

## What not to do

- Don't add framework wrappers, CSS-in-JS, or a second styling path. Components are Lit elements styled through CSS custom properties.
- Don't hard-code colors, spacing, or font values anywhere in `components/**`. Every value is a `var(--jh-…)`.
- Don't document the API in prose. It is generated; prose about it drifts.
- Don't rename `jh-*` tags or tokens. The `forge-` prefix is a v3 decision tracked elsewhere, not something to introduce piecemeal.
- Don't edit `CHANGELOG.md` files. Changesets write them.
