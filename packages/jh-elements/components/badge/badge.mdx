# Badge

[Guidelines](https://jackhenry.design/v2/components/badge/)

<hr />

A Badge is a visual indicator that represents numbers, such as counters. Badge also supports a dot-only variant in cases where an explicit count does not need to be displayed. Authors should refer to the [tag component](/docs/components-tag--docs) when needing to render non-numerical-related information.

## Usage

Import the `<jh-badge>` component:

```javascript
import '@jack-henry/jh-elements/components/badge/badge.js';
```

To use `<jh-badge>`: 

```html
<jh-badge count="3"></jh-badge>
```

## Count Behavior
- Badges display the `count` when set to a numerical value greater than or equal to 0. 
- When the `max-count` is set and surpassed by the `count`, the `max-count` will render with an appended `+` character as such: `max-count+`
- Authors can omit the `count` property to render a dot-only badge in cases where `count` does not need to be displayed. 

## Placement

Place the badge at the top-right of the element it relates to, overlapping the edge. Badge does not position itself — authors are responsible for placement.

## Accessibility

A badge, with or without a count, is a visual indicator. A number such as "3" means nothing to a screen reader user on its own. The meaning has to come from the element the badge belongs to, for example "Emails, 3 unread, button".

Assistive technology announces the badge's count on its own, separately from the element it is placed on, which puts it out of context. Put the badge's meaning in that element's accessible name instead.

Authors are responsible for providing the meaning of the badge and for deciding when changes to it are announced. How to do this depends on how the badge is used.

### Badge on an interactive element

When the badge is placed on an interactive element, such as a button or a link, use the accessible name of that element to convey the badge's meaning. Once the accessible name includes the count, set `aria-hidden="true"` on the badge so the count is not announced a second time, out of context.

```html
<jh-button accessible-label="Emails, 3 unread">
  <jh-icon-envelope slot="jh-button-icon-left"></jh-icon-envelope>
</jh-button>
<jh-badge count="3" aria-hidden="true"></jh-badge>
```

### Badge on a non-interactive element

When the badge is placed on a non-interactive element, such as an avatar, give that element a semantic role and an accessible name. For an avatar, use `role="img"`. Without a semantic role, the accessible name is not announced. Once the accessible name includes the badge's count, or for a dot-only badge its meaning, set `aria-hidden="true"` on the badge.

```html
<span class="avatar" role="img" aria-label="Jordan Lee, online">JL</span>
<jh-badge aria-hidden="true"></jh-badge>
```

### Standalone badge

When the badge is not placed on another element, there is nothing else to carry its meaning, so the badge labels itself. Set `role="img"` and `aria-label` on `<jh-badge>`. Do not set `aria-hidden="true"` on a standalone badge. It is the only element that carries the badge's meaning, so hiding it hides that meaning from screen reader users.

```html
<jh-badge count="3" role="img" aria-label="3 unread messages"></jh-badge>
```

When updates to a standalone badge need to be announced, use `role="status"` instead of `role="img"`.

```html
<jh-badge count="3" role="status" aria-label="3 unread messages"></jh-badge>
```

### Live announcements

Badge does not announce changes. Authors decide whether an update should be announced and when.

- To announce updates to a badge placed on another element, set `aria-live="polite"` and `aria-atomic="true"` on the originating element, and update its accessible name when the badge changes.
- To announce updates to a standalone badge, use `role="status"` as shown above.
- In both cases, update the `aria-label` whenever the `count` changes, so that the announced text matches the badge.

### WCAG

This component satisfies [WCAG 2.2](https://www.w3.org/TR/WCAG22/) AA success criteria. 
The following success criteria are of concern:

- [WCAG 1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html): All non-text content that is presented to the user has a text alternative that serves the equivalent purpose.

- [WCAG 1.4.1 Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): Color is not used as the only visual means of conveying information, indicating an action, prompting a response, or distinguishing a visual element.

- [WCAG 1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): The visual presentation of text and images of text has a contrast ratio of at least 4.5:1.

- [WCAG 1.4.4 Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html): Except for captions and images of text, text can be resized without assistive technology up to 200 percent without loss of content or functionality.

- [WCAG 4.1.3 Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): Status messages can be programmatically determined through role or properties such that they can be presented to the user by assistive technologies without receiving focus.

### What we provide

- To satisfy [WCAG 1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), the text and background color meet the minimum contrast of 4.5:1.

- To satisfy [WCAG 1.4.4 Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html), Badge can be resized without assistive technology up to 200 percent without loss of content or functionality.

### Author Guidance

- To satisfy [WCAG 1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html), convey the badge's meaning through the accessible name of the originating element, or of the badge itself when it is standalone, as described above.

- To satisfy [WCAG 1.4.1 Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) when using color to convey information, ensure the information is also conveyed in text via the originating element. 

- To satisfy [WCAG 1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) when using custom colors, be sure the minimum contrast requirements are met.

- To satisfy [WCAG 4.1.3 Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), announce badge updates that users need to know about, as described in Live announcements.
