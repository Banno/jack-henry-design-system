# Foundation documentation template

- Write the file to `/docs/foundations/<slug>.md` (match existing filename/casing conventions; multi-part topics use their full hyphenated slug, e.g. `voice-and-tone.md`).
- The following template structure SHOULD be used. Sections MAY be omitted if there is no relevant content in the source.

```markdown
# [name]

[Intro paragraph: a short, warm expansion of the one-line description, grounded only in what the spec says the foundation topic covers. Ignore if description field is empty or not present.]

- Section headings that follow the structure and heading level found in the spec.
- Group usage into two subheadings:
  - **Do**: Include rules MUST, SHOULD, and MAY
  - **Don't**: Include rules MUST NOT and SHOULD NOT; begin sentence with "Don't" or other appropriate negation.
```
